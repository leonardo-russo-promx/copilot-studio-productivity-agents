# Project planning

## Steps
1. Define the outcome and measurable success criteria. List in-scope and out-of-scope work.
2. Use technical analysis when repository or architecture details affect the sequence.
3. Break work into phases and tasks with deliverables. Record a dependency only when a task truly requires another.
4. Include acceptance criteria and validation steps mapped to the desired behavior.
5. Identify risks, mitigations, rollout/rollback, and decisions requiring product, design, security, or operations input.
6. If asked for estimates, provide ranges with assumptions and uncertainty; otherwise omit dates and estimates.

## Output
- Outcome / success measures
- Scope / non-goals
- Assumptions and current-state evidence
- Proposed approach
- Phases and dependency-aware tasks
- Acceptance criteria and validation
- Risks / mitigations
- Rollout / rollback
- Open questions and decisions

## Rules
- Do not create plan files unless the user explicitly asks.
- A plan is a proposal, not authorization to implement.
